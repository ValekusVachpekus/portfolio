# Портфолио Ильи Щеткова

Статический сайт на русском и английском: главная, 17 проектов с ролями и группами, достижения. Светлый фон, строгая типографика, прямые линии, без свечения и «пилюль». Без сторонних зависимостей, внешних шрифтов и запросов к GitHub при просмотре.

## Запуск

Нужен Node.js 22 или новее. Устанавливать пакеты не требуется.

```bash
npm run dev
```

Открыть http://127.0.0.1:4173. После изменения файлов перезапустить команду. `PORT=8080 npm run dev` меняет порт.

```bash
npm run check      # проверки и сборка
npm run build      # готовые файлы в dist/
npm run sync:github # получить даты и языки из GitHub
```

## GitHub Pages

1. Поместить **содержимое этой папки** в корень отдельного GitHub-репозитория, ветка `main`.
2. Settings → Pages → Build and deployment → Source: **GitHub Actions**.
3. Отправить изменения в `main` или запустить workflow `Deploy portfolio to GitHub Pages` вручную.

Workflow обновляет метаданные репозиториев, проверяет сайт и публикует `dist/`. Работает и в `username.github.io`, и в `username.github.io/repository/`: все ссылки относительные. Для 404 workflow передает базовый путь. При ручной сборке для вложенного адреса использовать `BASE_PATH=/repository/ npm run build`.

В этой сессии репозиторий и GitHub Pages не создавались, сайт не опубликован.

## Редактирование контента

- `content/profile.json` — имя, описание, навыки и контакты в двух языках. Источник: публичный профиль GitHub. `featuredProjects` задает проекты и их порядок на главной: Diskclean, ПДн-контроль, Chess CLI.
- `content/projects.json` — выбранные проекты. `group` определяет папку, `date` — дату релиза (`YYYY-MM-DD`), `role` — `solo` или `lead-frontend`. `name`, `description`, `contribution` могут содержать `ru` и `en`. `demo` — необязательная ссылка на работающий сервис.
- `content/groups.json` — названия и описания папок. Amazing всегда последняя. Другие папки сортируются по самой новой дате проекта, внутри каждой — новые выше.
- `content/achievements.json` — дипломы и сертификаты. Файлы положить в `public/documents/`.

### Даты и достоверность

Сначала используется ручная `date`, затем дата последнего опубликованного GitHub Release. Если релиза нет, берется дата создания репозитория с подписью «Создан»; она не выдается за дату релиза. Неизвестные даты не отображаются, такие проекты идут после датированных, сохраняя исходный порядок. Главная показывает вручную выбранные проекты из `featuredProjects`, независимо от дат и обновлений GitHub.

Часть GitHub-страниц при подготовке была недоступна. У соответствующих проектов стоит `needsReview: true`; их краткие описания основаны только на названиях, неизвестные технологии и даты не выдуманы. Перед публикацией желательно уточнить эти описания и даты релизов. Скрипт `sync:github` заполняет `content/github.json` (даты, основной язык, исходное описание), сохраняя ручные описания и даты. Он не заменяет редакторские тексты автоматически. При сетевой ошибке использует ранее сохраненные данные. В CI метаданные обновляются только для сборки, без коммита в репозиторий. Локально можно сохранить и закоммитить `content/github.json`.

Состав папки Amazing пока принят по названиям: OSB-проекты, Amazing RP Overlay, GAI Report Generator, AHK for GOS и Zakonka Silver. Перенос проекта — изменение `group`.

### Добавление достижения

Начальный список пуст: реальные дипломы пока не предоставлены. Добавить объект:

```json
{
  "id": "competition-2026",
  "title": { "ru": "Название достижения", "en": "Achievement title" },
  "issuer": { "ru": "Организатор", "en": "Organizer" },
  "date": "2026-10-28",
  "description": { "ru": "Краткое описание", "en": "Short description" },
  "file": "documents/diploma.pdf",
  "preview": "documents/diploma-preview.jpg"
}
```

`preview` и `description` необязательны. Поддерживаются PDF, PNG, JPG, WebP и AVIF. Для PDF без превью показывается аккуратная обложка. PDF открывается в новой вкладке; изображение — в диалоге с закрытием по Escape, кнопке и фону. Без JavaScript изображение открывается обычной ссылкой. Достижения сортируются по дате, новые выше.

## Проверка

`npm run check` проверяет наличие всех выбранных проектов, роли, RU/EN, относительные ссылки для двух вариантов GitHub Pages, сортировку, приоритет ручных дат, последнюю позицию Amazing и безопасные пути к документам.

Перед публикацией: проверить мобильную верстку, поиск по проектам, сворачивание групп, переключение языка, контакты; после добавления дипломов — просмотр изображений и открытие PDF.

В среде подготовки локальный сервер и Chromium заблокированы системными ограничениями (`EPERM`); визуальная браузерная проверка не выполнена. HTML, ссылки и данные проверены автоматически.
